Sigillum is a local-first operator console for your Ethereum treasury. A quick orientation before you create a vault.

Everything runs on this machine
The daemon listens only on loopback, and your private keys never leave this computer. No account, no cloud, no telemetry.
Your data is an encrypted vault on this disk
State lives in an encrypted vault under ~/.sigillum that only you can unlock. You can snapshot and back it up whenever you want.
Privacy is built in, but you choose your providers
Stealth one-time receive addresses keep deposits unlinkable. Any RPC provider you add later can see the addresses you query through it, so you choose and can partition providers.

Protect payer privacy on sweeps
Block consolidations and sweeps that would publicly link your payers (fail-closed). This covers addresses that would land in the same destination (single-hop common-recipient linkage). You can route each payer to a distinct destination, and you can change this anytime in Treasury policy.

Scope: detects when different payers would sweep to the SAME destination. It does NOT cover gas-funding linkage, amount or timing correlation, downstream re-merging of per-party destinations, or multi-hop flows — keep per-party destinations separate.

Enable Merkle claim execution (optional)
Off by default. Claim execution stays blocked unless ALL of these hold: this policy is enabled, the claim uses the merkle-distributor-v1 adapter, its simulation passed, the claim contract is marked trusted in the risk catalog (or carries a claim_execution_reviewed note), and you explicitly approve the step.       What Sigillum does today

      A local vault plus an Ethereum operator console. Treat the workspace sections as distinct jobs, not one scrolling checklist.

      1. Treasury

      Watch tracked balances, routing readiness, policy posture, and receive-address allocation in one roll-up.

      2. Wallets

      Save provider profiles, then choose a wallet family: stealth wallets for tracked deposits and queue work, or seed/xpub receive wallets for address visibility.

      3. Operations

      Run inventory discovery, tracked deposits, queue processing, and maintenance cycles. Operator workflows currently run on stealth wallets.

      4. Secrets

      Store connection keys and encrypted secrets, organize compartments, and move values between compartments when needed.

      5. Security

      Manage hardware keys, export encrypted snapshots, and inspect the audit trail before anything sensitive.
